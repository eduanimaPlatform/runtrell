# テスト対応表

比較基準は既存調査証拠。Rig run: unit 104 / doctest 13（通常9・compile_fail4）。core: unit 1507 / integration 33。全core機能は採用しない。件数合わせを目的にしない。

今回の最終実行件数・コマンドは[initial-build.md](initial-build.md)。以下は原本の関数名と移行先の対応。import変更・formatting・帰属headerは全体に適用。testsのskip/ignore追加やassertion弱体化はない。

## 意図した変更

- `max_turns` API/保存field/MaxTurns errorを削除。通常tool反復に総回数上限はない。再開とmalformed継続の新期待を先に失敗させた。既存104件を維持し、上限依存の3ケースを更新。
- RunSpecは未知fieldを拒否し、旧max_turnsを黙って無視しない。保存envelopeは独立format 1、未知版・Rig 2/3/4/5を拒否。format拒否testを更新。
- retry上限（invalid call / malformed / output repair）は障害修復の設定として継承。token/costの共有台帳は次段階。Doneは候補であり、既存best-effort outputも業務成功にはならない。
- `run_requests_stay_unwind_safe`から非採用AgentHook/DispatchActionのassertionのみ除去。RunSpec/PreparedRequestのunwind安全性は維持。同様にprovider_optionsのeffect/serve assertionのみ除去。
- requestのMockCompletionModel経由テストは同期のrequest validation・response stop・history replayへ移す。annotationsはToolDefinitionへ直接設定。pricing testはホストが渡すCost::pricedに変更し、不完全値のserde/加算assertionを維持。
- footprintのserve/erased handlerは採用しない。ホストのadapterが公開definitionとTouchesを読むfixtureへ移し、path/不正引数/unknown toolの3assertionを維持。

## 統合・不採用範囲

- `core/src/streaming/tests.rs::a_partial_turn_after_an_error_is_marked_failed`の失敗stop/内容保持条件を`tests/host_contract.rs::partial_stream_failure_keeps_content_and_cannot_be_a_successful_turn`へ移行。transport生成のfixtureを汎用CompletionResponseへ接続。
- 同`an_error_is_the_last_item_and_finish_returns_it`は非採用model driverのpoll/finish契約。protocolにstream readerをstubとして作らない。item/eventとrun assemblerの中断・partial・終了理由のtestsを継承し、外部driverでerror後pollを止める責務をREADMEへ記載。driver実装時の受入条件として保持（今回の達成とはしない）。
- core integration 33はHTTP/provider wire/driver/catalog/telemetryの実行試験。該当実装を採用しないため原本targetのままは移さない。公開crate境界はhost_contract・host_drivenへ統合し、opaque継続、失敗metadata、構造化判断を確認。decoder/pull protocol/provider.websocket等は非採用範囲。
- `error/encode_tests.rs`はprovider wireのencode、`error/retry.rs`はprovider HTTP header/bodyからretry時間を解釈する機能。採用せず、ホストが分類済みreportを渡す。errorのtool/source-chain/serde/code/refusal testsは保持。
- 採用しないprovider/embedding/vector/loaders/rerank/transcription/audio-image generation/client/catalog/operation/driver/wire/serve/telemetryのtestsは製品の試験対象にしない。元1507件全てが現行契約ではない。
- fixtureはRust内synthetic値のみを継承。HTTP cassette/外部サービスfixtureは不要。structured_outputの既存直接testsはなく、runのoutput/prepare testsとdoctest、追加host_contractでpresence-onlyの限界を明示。
