# Workspace・Artifact・検証・context（2b、schema 1）

2aの未実装WorkspaceStore/ArtifactStoreを、actor（tenant/Run/Agent）に結び付くAccessで置き換える。RunStore/OperationStore/BudgetAuthority/Schedulerのtraitは変更しない。所有者以外は既定拒否。子Runの共有は信頼済みhostがRunRecord.parentを照合して版付きgrantを発行する。共有は読取/更新を分け、更新後の再共有を必要とする。

namespaceごとにmanifest revisionをCASし、一括write/delete/exact-replaceは全件を検査して1回commitする。ファイルrevisionはnamespace commit revisionを使いABAを防ぐ。snapshot hashはnamespace・revision・ソート済みfile manifestへ結び付く。copyの入力snapshotを固定し、回収はそのsnapshotと現行manifestの一致を条件とする。削除も明示Changeとして回収する。無関係なnamespaceは独立する。

保存受付はStagedでありread/finalize対象外。commit成功のみSaved。in-memoryはprocess内保証。local FSはrootのdirectory FDからNOFOLLOWで各componentを開き、固定名状態fileをrename/fsyncで更新する。symlink/hardlink/非regular fileを拒否。namespace単位のOS lockを持ち、複数instance/process間でもCASする。論理pathをOS pathに使わない。root設定自体もcomponentごとにNOFOLLOW。容量/保持/削除はWorkspace/中間/最終Artifact/checkpoint/logを別policyで設定する。期限到達は削除許可の条件で、自動消去完了ではない。

Artifactは保存済み不変blob・manifest・生成元を持つ。外部参照と範囲read/打切り表示でcontextへ全文を入れない。Validatorはhostが登録するRust実装で、Workspace内の実行fileを検証器としてロードしない。診断はcode/severity/artifact/file/field/span/cause/hint。検証証跡は対象hash・manifest・basis/config/validator版へ結び付けてstoreに保存する。Finalizerは現在のsnapshotと信頼済みreceipt集合を同じnamespace transactionで検査し安定completion IDを保存する。構造化判断にも同じTargetを用い、ファイルを要求しない。業務ownerへの反映とRun成功は2aの別barrier。

contextは開始revision/high-waterを固定し、構造化した目的・制約・未完了操作・Artifact/出所を保持する。圧縮は完全な成功応答のみCAS保存。途中のappendでrevisionが進めば拒否し、元履歴を保持する。要約要求はRuntime.dispatchのCompactionとして予約・記録する。promptは自社文面。tool catalogはモデルに提示したdescriptor全体のdigestを固定、現行実装と一致しなければ拒否し、現在policyも毎回照合する。toolは既定直列、競合範囲と版CASを宣言する。

## 初期backendの具体的な制約

論理pathはportable ASCII（英大小文字・数字・`._-/`）を受け付け、空component・`.`・`..`・絶対path・backslashを拒否する。manifest内のfile/親directoryについて大小文字だけ異なる別名も拒否し、`Cargo.toml`等の普通の大文字名は利用できる。同一fileへの複数exact-replaceは各digestを開始内容へ照合し、staging上で順番に置換して1commitする。

local rootはhost専有の既存directoryを設定する。root自体にもsymlinkを許さないので、macOSの`/var`経由はhostが実pathを選ぶ。論理fileはOSのpathへ直接露出せず、将来のcopy/mountの実体化はExecutionBackendの責務。保存状態はnamespace単位のJSONであり、大きいblobもこの初期backendでは同じ状態file内に保持する。範囲APIの返却は有限だがdiskの部分read最適化やthroughput/SLOを保証しない。host processのSIGKILL中に残る未commitの`stage-*`は正本として読まない。自動GCと電源断試験は未提供であり、保存済みとの報告には含めない。

retentionは2a Clockと同じUnix millisecond。class cleanupは保持中/確定済みblobが残ればPending。確定済みblobはFinal policyも適用した個別deleteを使う。Workspace/Checkpointの全体削除にはowner、期待revision、明示retain境界が必要。Run終端を自動削除許可にしない。context圧縮は明示`Runtime::compact_context`を提供し、自動起動閾値は固定しない。hostは構造化contractの投入と圧縮後contextのモデル入力への採用を決める。2a protocol checkpointの内部履歴そのものを置換する実装ではない。
